#+TITLE: ZSA Voyager keymap (local QMK)

Layer overview: [[file:layout.org][layout.org]].

* Configure
- Keys and layers: =keymap.c= (layer 0 base, 1 numbers/symbols, 2 F-keys).
- Hold timing and misfire guards: =config.h=, plus =chordal_hold_layout= and
  =get_tapping_term= in =keymap.c=.
- Features on/off (Caps Word, ...): =rules.mk=.
- LEDs: =keymap.c=. Colours are {hue, saturation, brightness}, 0-255; the
  board brightness keys scale them all.
  - All colours: the =themes= table (5 themes: layer colours + key highlights).
  - Bright/Dim levels: =BRIGHT_VAL=, =DIM_PERCENT=.
  - Thumb layer keys: =LAYER_TAP_VAL= (their colour is the target layer's).
  - Which key gets which colour is worked out from the keymap at start-up, so
    moving a key moves its colour. What each colour means: =layout.org=, LEDs.
  - Idle timeout (lights off): =RGB_MATRIX_TIMEOUT= in =config.h=.

* Flash
Uses ZSA's QMK fork in =../qmk-zsa= (branch =firmware25=), where
=keyboards/zsa/voyager/keymaps/local= links to this folder.
#+begin_src sh
cd /var/projects/atlas-iade/dev/zsa/qmk-zsa
qmk flash -kb zsa/voyager -km local
#+end_src
When it prints "Bootloader not found", hold Space and press the top-right key
(QK_BOOT, lit red), or press the reset button on the Voyager.
Both boards use the same STM32 bootloader, so =qmk flash= writes to whichever
board is in reset: plug in only the board you mean to flash.
Keymapp is not needed (it segfaults here).

* Workflow
1. Edit the files here. Each =LAYOUT_voyager(...)= has exactly 52 keys
   (4 rows of 12, then 4 thumbs); =KC_NO= = off, =KC_TRANSPARENT= = base key.
2. Check it builds: =qmk compile -kb zsa/voyager -km local= (in =../qmk-zsa=).
3. Flash: =qmk flash -kb zsa/voyager -km local=, then press reset.
4. Happy with it: commit. =git diff= shows changes, =git checkout <file>= undoes them.
A broken layout cannot brick the board: the bootloader is never overwritten,
and the reset button always gets back to it.
